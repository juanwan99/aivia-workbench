| 必须 | 说明 |
|------|------|
| **Web** | 登录即用，挂现有 IP/域名 |

## 2. 对比结论（云端优先）

### 有没有「比 OpenWork 更适合当主线」的？

**有。** 只要主线是 **网页版**，OpenWork **不是**最优主底座。

| 排名 | 主候选 | 理由 |
|------|--------|------|
| **1** | **Dify** | 真 Web、Agent/工作流一体、Docker 上现网、接 DS、可做「课件应用」强制步骤与文件、中心化知识库 |
| **2** | **LibreChat 加固** | 已是 Pico 壳、MIT、登录；但交付纪律与 Agent 曾翻车，要大补而非换皮 |
| **3** | **Open WebUI** | 起最快、社区大；任务型工作台与强制交付要自建较多 |
| **4** | **FastGPT** | 知识库/应用国内熟；办公 Agent 完整度看 Spike |
| **验真** | **Magic** | 一体办公叙事最满，星少，必须实装 |
| **核增强** | OpenHands / 服务端 OpenCode | 侧挂强 Agent，不当唯一教师门户 |
| **二期** | OpenWork | 本地文件深处理 |

### 和「没有更好就用 OpenWork」

在 **云端 Web** 约束下：**有更好 → Dify（默认主推荐）**。  
OpenWork 保留为 **本地二期**，不是「没有 Web 方案时的将就主线」。

## 3. 推荐架构（选型向）

```text
现有服务器 + 域名
    │
    ▼
Dify（Web 主台：应用/Agent/工作流/知识库）
    │
    ├── DeepSeek API
    ├── 文档工具（生成 HTML/DOCX/PPTX → 可下载）
    ├── 中心知识库/模板（平台治理）
    └── 后置：edu JWT、OnlyOffice 在线精修（可选）

二期：OpenWork/桌面轻端（本地深文件）
```

**交付硬规则仍独立于厂商：** 要文件必须有文件。
