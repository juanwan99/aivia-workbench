# 交付硬规则（阶段 B · B1）

来源：`docs/RESPONSE-LOGIC.md` R1–R8。对标 WorkBuddy **行为**，不抄闭源。  
落地环境：**Dify Web 应用 / 工作流**（主线）。

| # | 规则 | 落地方式（优先应用提示/工作流节点，禁止乱改 Dify 核） |
|---|------|------------------------------------------------------|
| R1 | 用户目标优先任务化 | 系统提示：可执行任务优先于闲聊结束 |
| R2 | 信息足够则执行 | 缺关键参数最多澄清 1 次，然后默认并执行 |
| R3 | 需要文件/课件 → 必须出件 | **工作流最后节点生成并提供下载**；禁止只贴长代码 |
| R4 | 成功 ⇒ 可定位 Artifact | 终态含下载入口或明确失败 |
| R5 | 过程可见 | 依赖 Dify 步骤/节点展示 |
| R6 | 边界默认生效 | 应用权限与知识库范围 |
| R7 | 可停、可再试 | 用产品停止能力；失败可重试 |
| R8 | 终态人话，禁止假绿 | 无文件 = 失败/需重试 |

## 验收尺子（B 出口）

多轮「要课件」**10 次**，空成功 = **0**。  
判定：每次文件类需求必须有可下载产物。

## 配额 / 超时（B3）

在 Dify 当前版应用/工作空间配置中设置限流与超时；数字由业主试点前定，记入 Issue。

## 品牌（B4，可选）

站点名/关于文案；不借机大改交互骨架。

## 禁止

- 无 G1 证据宣称交付完成  
- Agent 直写 edu 业务库  
- 主线改回「仅桌面 OpenWork」
