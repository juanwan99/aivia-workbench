## 1. 调查目标

产出一份 **可执行的对标总表**，使后续开发只对照表开工，避免「感觉要有」：

1. WorkBuddy **公开能力清单**（尽量全）  
2. 每条标注：**终端用户** vs **管理员/运营后台** vs **企业治理**  
3. 每条对照 Aivia **现状**（有 / 部分 / 无）与 **建议落点**（Chat / Dify 控制台 / bridge / 新 Admin / 二期桌面）  
4. **分期建议**（P0 个人办公交付 · P1 管理后台 · P2 桌面/IM/生态）  
5. **不做清单**（法律/架构红线）

## 3. 能力域框架（调查时按域填满，禁止空域）

调查人必须为每域列出 **≥N 条原子能力**（见 RUNBOOK），并分层：

### 域 A · 对话与任务编排（用户）

自然语言任务、多步计划可见、停止/重试、多会话、历史、推荐/技能入口…

### 域 B · 办公交付物（用户）

文档 Word、表格 Excel、PPT、PDF、HTML/网页、图片/海报、报告、邮件稿…  
**含：下载、本机打开、改稿、多文件**

### 域 C · 文件与知识（用户 / 部分管理）

上传再加工、本地文件（桌面特有）、知识库、模板中心、共享资产…

### 域 D · 工具与连接（用户 / 管理配置）

浏览器/搜索、代码、数据清洗、连接 IM/文档/会议、插件/技能市场…

### 域 E · 多 Agent / 专家角色（用户感知 + 管理配置）

多专家、并行任务、角色切换…（配置多在后台）

### 域 F · 账号与个人设置（用户）

登录、偏好、模型选择（若有）、用量查看…

### 域 G · **管理员 / 后端**（业主强调重点）

| 子域 | 例 |
|------|-----|
| G1 组织与成员 | 邀请、角色（管理员/成员/只读）、停用 |
| G2 权限与安全 | 工具白名单、IP、审计日志、禁写业务库策略 |
| G3 用量与计费 | 额度、模型配额、限流策略 |
| G4 应用与技能治理 | 发布应用、推荐问题、模板库、技能上下架 |
| G5 知识与数据 | 租户知识库、连接 edu 只读、数据分级 |
| G6 可观测 | 会话日志、失败率、空成功监控、下载成功率 |
| G7 品牌与入口 | 域名、应用名、默认 Chat、公告 |

> **原则：** WorkBuddy 企业控制台类能力 → Aivia 优先映射到 **Dify 控制台 + 自建 Admin/ops + bridge**，**不要**全部做成老师 Chat 里的按钮。

### 域 H · 端与形态

Web / 桌面 / 小程序 / 企微·飞书·钉钉 bot …  
Aivia 现行主形态 **Web**；桌面/IM 标二期除非业主改口径。

### 域 I · 教育垂直（Aivia 增量，WB 可能弱/无）

课件、教案、学情表、edu 只读、拒写成绩库…（已有部分：SCENE-FULL）
