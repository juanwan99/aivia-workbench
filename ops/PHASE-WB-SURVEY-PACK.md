## 0. 「有深度」的定义（不过线 = 调查 FAIL）

| 维度 | 必须做到 | 禁止充数 |
|------|----------|----------|
| **UI 布局** | 主壳分区、导航、任务区、产物区、设置/管理入口线框或结构化笔记 | 只写「有侧边栏」一句话 |
| **响应逻辑** | 发任务后：计划/步骤是否可见、流式/阶段态、停止重试、失败提示、下载/打开产物路径 | 只抄官网广告语 |
| **业务组织** | 会话/任务/项目/专家/技能/文件/团队 的层级与从属；用户 vs 管理员看到的不同树 | 扁平功能名列表无关系 |
| **能力全景** | 矩阵仍 ≥40；每条能指回「在哪个屏、哪条路径点到」 | 网上功能名堆砌、指不出入口 |
| **证据** | 本机截图（打码隐私）+ 路径笔记；`sources.md` 区分 `local-UI` / `web` | 纯 URL 列表 |

**网搜：** 可作交叉验证与企业版文案补充，**权重低于本机。**

## 2. 深查作业结构（按序）

### D0 · 环境

### D1 · 信息架构与 UI 布局（出图+文）

至少覆盖并截图/线框：

1. 主窗口总览（顶栏/侧栏/主区/底栏）  
2. 新任务 / 对话输入区  
3. 任务进行中（计划/步骤/工具态若可见）  
4. 产物/文件交付区  
5. 历史/会话列表  
6. 技能/专家/模板入口（有则）  
7. 设置  
8. **管理/团队/控制台**（有权限则必做；无则注明「无管理权限」）  

交付：`ops/evidence/wb-survey/ui/README.md` + 截图；`ops/WB-IA.md`（信息架构：树状组织关系）。

### D2 · 响应逻辑（行为剧本）

对 **≥5** 条真实任务走通并记时序（用户操作 → 界面变化 → 终态）：

| 剧本例 | 观察点 |
|--------|--------|
| 生成一份文档/报告 | 是否多步、产物形态、如何打开/下载 |
| 表格/数据分析 | 上传或本地文件？改表？导出？ |
| 只要大纲/短答 | 是否仍硬塞文件 |
| 失败/拒绝类 | 提示是否人话 |
| 连续两任务 | 是否串台、上下文如何切 |

交付：`ops/WB-RESPONSE-LOGIC.md`（时序 + 状态机文字：空闲/规划/执行/交付/失败）。

### D3 · 业务组织关系

必须画清（可用 mermaid/缩进树）：

- 用户、工作区/项目、会话、任务、子步骤、产物文件

- 团队、成员、角色、权限（管理端）  
- 哪些配置在 **前台**、哪些在 **后台**  

交付：`ops/WB-ORG-MODEL.md`。
