## 0. 阶段 B 到底解决什么

阶段 A 证明了：**现网能开、能聊、至少能出两次 HTML。**  
阶段 B 要证明的是：**像专业工作台一样「不骗人」——稳定出件、可改稿、过程可见、失败诚实、平台有模板/边界，而不是碰运气的演示。**

| 用户对专业平台的默认真相 | 阶段 B 必须做到 |
|--------------------------|----------------|
| 说「要课件」就有文件 | 强制出件；禁止长代码当交付 |
| 改一版仍有文件 | 多轮改稿可下载（延续 G1+） |
| 知道系统在干什么 | 过程可见（步骤/节点/工具） |
| 坏了说坏了 | 无文件 ≠ 成功（G4 + 10 次尺子） |
| 不用自己建库 | 平台侧模板/知识库可选 |
| 不会一次烧光额度 | 超时/限流/配额 |
| 入口像产品不是实验 | 默认应用可被普通人点到 |

**明确不对标、不做：**

- 像素抄 WorkBuddy / ChatGPT 皮肤  
- 重写 Dify 核  
- edu 写库  
- OpenWork 双主线  
- 把「容器绿 / 模型通」当产品绿

## 1. WorkBuddy 向行为矩阵（clean-room · 必须落到 Dify）

来源：`docs/RESPONSE-LOGIC.md` + `docs/DELIVERY-RULES.md`。  
**落地位置：** 默认课件应用的系统提示 +（优先）Chatflow/Workflow 末节点出文件；**禁止**只写在仓内 md 却不进运行时。

| ID | 专业行为 | Dify 落地最低标准 | 验收 |
|----|----------|-------------------|------|
| R1 | 目标任务化 | 提示：用户要课件/教案时进入生产模式，不闲聊结束 | 10 次中不以纯闲聊收尾 |
| R2 | 信息够就做 | 缺学科/年级最多问 1 次，否则默认「初中通用」并执行 | 不得连环反问当成功 |
| R3 | 要文件必出件 | **必须**有可下载 `.html`/`.docx`（或平台产物链接） | 空成功计 FAIL |
| R4 | 成功=Artifact | 终态回复含文件名或下载入口；无则 failed | 抽检终态文案 |
| R5 | 过程可见 | Agent 工具步或 Workflow 节点可见 | G2 |
| R6 | 边界默认 | 知识库/权限不越权；不编造「已写入学校库」 | 抽检 |
| R7 | 可停可再试 | 产品停止按钮可用或失败后可新开一轮重试 | 记一次 |
| R8 | 禁止假绿 | 无文件不得显示完成/成功 | G4 + 10 次 |

**对标一句话：** 学的是「任务 → 执行 → 产物 → 诚实状态」，不是学皮肤。

## 3. 工作包拆解（按序，可同日串行）

### B0 · 开场复验（30–60 min）

1. 打开 `https://workbench.aivia.asia`（记证书警告：有/无）  
2. 登录 → 打开默认课件应用  
3. 复跑 G1 话术一次（防回归）  
4. **补 G4**：故意中断/要超大不可能文件/断模型（择一可控方式）→ **不得**「成功但无文件」  

记录进 `ops/B-PATH-RUNBOOK.md`。

### B1 · 交付硬规则进运行时（核心）

**目标：** 规则不在文档里「待用」，而在**默认应用**里生效。

最低实现（二选一，推荐甲+乙组合）：

**甲 · 系统提示固化（必做）**  
将 `skills/courseware-html/SKILL.md` 纪律译入应用 System Prompt，至少含：

```text
- 用户要课件/HTML/教案/可下载文件时：必须给出可下载产物。
- 禁止只贴长代码并说「请自行保存」。
- 无法出件时明确失败，不要说「已完成」。
- 信息不足时最多澄清一次，否则用合理默认并执行。
- 终态说明文件名或下载方式。
```

**乙 · 工作流强制出件（强烈推荐，更硬）**  
Chatflow/Workflow：

1. 开始 → LLM 生成完整 HTML（约束单文件、内联 CSS）  
2. **代码/文件节点**写出 `.html`（或 Dify 文件变量）  
3. **结束节点**只暴露「文件/下载」；无文件则走失败分支  

应用显示名建议升级：`Aivia 课件`（可保留阶段 A 名作别名）。  
模型：DeepSeek `deepseek-chat`（与 PIN 一致）。

**验收：** 任意新会话，一句话要课件 → 有下载；掐掉文件节点或模拟失败 → 不显示成功。

### B2 · 双能力默认可用

| 能力 | 触发话术 | 产物 | 来源资产 |
|------|----------|------|----------|
| HTML 课件 | 「做一份…HTML 课件」 | `.html` 可打开 | `skills/courseware-html` |
| 教案 | 「写一份…教案」 | `.docx` 优先；否则可下载 md/html 并标明格式 | `skills/lesson-plan-docx` |

要求：

- **一句话可触发**（不必用户懂 Workflow）  
- 同会话改稿至少 1 次仍出文件（B 延续 G1+）  
- 质量底线（非美工大赛）：有标题、目标、正文结构；HTML 浏览器可开；不要求动画炫技  

可选：第二应用「Aivia 教案」或同一应用路由两种意图。

### B3 · 限流 / 超时 / 配额

防止「专业平台样子、账单业余」。

| 旋钮 | 建议起点（可调，须记 Issue） |
|------|------------------------------|
| 单次生成超时 | 按 Dify 应用/模型超时合理值 |
| 工作空间/用户日调用 | 试点前与业主定数字 |
| 并发 | 小团队够用即可 |
| 失败重试 | 用户可手动再试；避免死循环烧 token |

**验收：** 配置截图或文字说明进 Issue（**无密钥**）；至少验证「超时/限额后有人话提示」一次。

### B4 · 品牌最小（可选，不挡出口）

- 站点/应用名：Aivia Workbench / Aivia 课件  
- 关于/欢迎语一行：任务 → 产物 → 诚实状态  
- **禁止**借机大改交互骨架或抄 WB 皮  

### B5 · 中心知识库 / 模板（平台侧）

对标专业平台「组织资产」而非「老师本机建库」。

最低交付：

1. Dify 知识库 1 个：如「课件结构模板 / 学科示例提纲」（脱敏公开教材结构即可）  
2. 默认应用挂接该库（可选检索）  
3. 或「模板变量」：固定 HTML 骨架由工作流注入  

**验收：** 新教师账号（或模拟）**不自建库**也能出结构完整课件。  
不做：全学科海量库、版权不明全文灌库。

## 4. 出口尺子 · 10 次要文件电池（M3）

### 4.1 规则

- 环境：默认课件（及教案）入口，浏览器  
- 模型：DeepSeek  
- **N = 10**，**空成功必须 = 0**  
- **空成功定义：** 用户明确要文件/课件/教案，终态像成功或完成，但**没有**可下载/可打开产物  
- 下列**不算**空成功：明确失败 + 可重试；用户只要问答不要文件  
- 每次记：话术 ID、产物文件名、PASS/FAIL、备注  

### 4.2 标准 10 话术（可微调学科，不可删「出件」意图）

| # | 话术 | 期望 |
|---|------|------|
| T1 | 请做一份初中生物「豌豆杂交」HTML 课件，要能下载 | `.html` |
| T2 | （同会话）再加 3 道练习题，更新后仍给我可下载 HTML | 新/更新文件 |
| T3 | 新会话：高一数学「二次函数」HTML 课件，能下载 | `.html` |
| T4 | 写一份初二语文《背影》一课时教案，要可下载文件 | 教案文件 |
| T5 | 做一份小学科学「水的三态」HTML 课件 | `.html` |
| T6 | （同会话）把学习目标改成三条可测量表述，再导出 | 可下载 |
| T7 | 只要大纲不要文件：二次函数知识点列 5 条 | 允许无文件 |
| T8 | 立即要文件：英语「一般现在时」HTML 课件下载 | `.html` |
| T9 | 信息极少：「课件」二字（应默认主题并出件或明确要主题后出件） | 不得空成功 |
| T10 | 故意施压：先答应做课件，若你只能聊天就说做不到——仍必须尝试出件或明确失败 | 无假绿 |

**计分：**  
- T1–T6、T8–T10 中凡「要文件」者：无下载 = **FAIL（空成功）**  
- T7：有清晰大纲且不假装已交文件 = PASS  
- **任一空成功 → 阶段 B 出口 FAIL**，修应用后重跑失败项 + 至少再抽 3 项  

### 4.3 附加专业抽检（建议同日，记 RUNBOOK）

| ID | 项 | 通过 |
|----|-----|------|
| G2 | 至少 2 次过程可见 | 节点/工具/步骤 |
| G4 | 1 次反空成功 | 无假绿 |
| G1b | 教案可下载至少 1 次 | T4 |
| 改稿 | T2/T6 | 同会话仍有文件 |

## 5. 质量底线（防「有文件但是垃圾」）

有文件仍可能是伪交付。B 阶段抽检 **≥3 个 HTML**：

| 检查 | 标准 |
|------|------|
| 可打开 | 双击/浏览器无致命空白 |
| 主题相关 | 标题/正文含用户课题关键词 |
| 结构 | 至少：标题、目标或要点、正文块 |
| 非半截 | 非明显截断到半句结束 |
| 非纯代码墙交付 | 终态是下载而非「复制下面一万字」 |

不要求：精美动效、印刷级排版、100% 学科严谨（试点后再提）。

## 8. 风险与反模式

| 反模式 | 正确做法 |
