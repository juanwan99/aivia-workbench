## 1. 业主口径

**可以继续使用之前的服务器、公网 IP 与域名体系。**  
不强制新购机器或新注册主域名才能启动 **Dify Web 主线**。

## 2. 角色分工

| 层级 | 跑什么 |
|------|--------|
| **现有服务器** | **Dify（Docker）= 主入口**；过渡期 Pico；日后 edu 桥 |
| **用户浏览器** | 打开 `workbench` 子域（或指定 URL）使用工作台 |
| **用户本机（二期）** | 可选 OpenWork 等桌面，**不占主入口** |

## 3. 域名建议

| 主机名 | 用途 |
|--------|------|
| `pico.aivia.asia`（或现网 Pico 域名） | **过渡保留**旧站；大功能冻结 |
| **`workbench.aivia.asia`（示例）** | **Dify Web 主台**（反代到 Docker 发布端口） |
| 根域 `aivia.asia` | 按品牌需要跳转 |

用 Caddy/Nginx/Traefik **按 Host 分流**；证书分域签发或续期。

> 具体现网 IP、SSH、面板账号：**不进 Git**。

## 4. 阶段与基建依赖

| 阶段 | 是否必须 DNS/反代 |
|------|-------------------|
| A 装 Dify + G1 | **建议**挂子域 HTTPS；亦可用 IP:端口做内测，正式入口应 HTTPS 域名 |
| B 应用/纪律 | 同主入口 |
| C edu 桥 | 是（桥服务建议同机或侧车 + HTTPS） |
| D 试点 | 稳定主入口；桌面客户端可选 |

## 5. 禁止

- 无备份时直接拆掉 Pico 域名  
- 密钥写入仓库  
- **OpenWork 服务硬塞成与 Dify 并列的「主站」**  
- 清空旧服无回滚方案

子域或端口有变 → 更新本节与 HANDOFF §3.1，Issue #1 留一句。
