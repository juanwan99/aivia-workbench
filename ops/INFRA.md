## 1. 业主口径

**可以继续使用之前的服务器、公网 IP 与域名体系。**  
不强制新购机器或新注册主域名才能启动 OpenWork 主线。

## 2. 角色分工

| 层级 | 跑什么 |
|------|--------|
| **用户本机** | OpenWork 桌面客户端 + DeepSeek（阶段 A/B 主路径） |
| **现有服务器** | ① 过渡期 Pico ② 文档/下载/状态页 ③ 日后 edu 桥与配置 API ④ 可选 Web 门户 |

OpenWork **不是**「在 8080 上再起一个与 LibreChat 同构的 Pico 替身」；不要用旧部署脚本假装装好了 OpenWork 服务端。

## 3. 域名建议

| 主机名 | 用途 |
|--------|------|
| `pico.aivia.asia`（或现网 Pico 域名） | **过渡保留**旧站；大功能冻结 |
| `workbench.aivia.asia` 或 `desk.aivia.asia`（示例） | 新线说明、安装文档、安装包链接、日后网关 |
| 根域 `aivia.asia` | 按业主品牌需要跳转 |

用 Caddy/Nginx/Traefik **按 Host 分流**；证书分别为子域签发或续期。

> 具体现网 IP、SSH、面板账号：**不进 Git**。由业主/运维持有；执行窗需要时走私密渠道。

## 4. 阶段与基建依赖

| 阶段 | 是否必须先改 DNS |
|------|------------------|
| A 安装 + G1 | **否**（本机客户端） |
| B Skills/纪律 | **否** |
| C edu 桥 | **是**（桥服务建议挂现有机器 + HTTPS 子域） |
| D 试点 | 视是否统一下载入口 |

## 5. 禁止

- 无备份、无并行入口时直接拆掉 Pico 域名  
- 密钥写入仓库或公开 Issue  
- 客户端硬编码依赖旧 Pico Agent 当 OpenCode 替代核  

## 6. 回写

若实际子域或 IP 用途有变，更新本节与 HANDOFF §3.1，并在 Issue #1 留一句。
